## 功能证据

| 项目 | 当时结果与边界 |
| --- | --- |
| 输入模式与颜色 | 连续跟随探针记录状态和颜色写入，用户确认实际显示正确。 |
| 多标签与分屏 | 同一终端窗口的三个会话分别初始化，`WT_SESSION` 不同。重复启动没有留下第二个 worker，用户确认颜色跟随。 |
| Atuin | 自动检查显示 `running=true`，keybinding 名称和 hook 数量未变。用户另行测试搜索、取消、选择记录和返回编辑，反馈没有问题。 |
| 退出清理 | 启动基准的 30 次启用样本全部通过 worker 随根 Nu 退出检查。资源测试的 10 个 worker 和测试 Nu 已清理。 |
| 静态与单元检查 | 7 项 Rust 单元测试、格式检查和 `--all-targets` Clippy 通过。 |

单元测试覆盖状态分类、查询失败、颜色参数、OSC 指令、写入重试、CLI 参数、会话标识和 Windows 参数引用。颜色显示结论来自用户观察。

早期 worker 继承 Nu 管道句柄，导致 `complete` 等待长期 worker，启动基准超时。禁止句柄继承后，最终 30 次启用样本完成。这项结论来自实际交互式 Nu 启动，不能只用参数引用测试替代。

## Nu 启动时间

同一台电脑交替测量关闭和启用各 30 次，每轮交换顺序。临时配置加载用户实际 `config.nu` 及环境配置，禁用历史保存。首个提示符能执行命令后，读取 `$nu.startup-time`。测量没有以跳过日常配置的 `nu -n -c` 代替交互式启动。

| 指标 | 关闭 | 启用 | 两组指标之差 |
| --- | ---: | ---: | ---: |
| 中位数 | 273.0005 ms | 294.6774 ms | +21.6769 ms |
| P95 | 364.7360 ms | 421.7629 ms | +57.0269 ms |

共 60 个样本，30 个启用样本的 `WorkerCleanup` 均为 `true`。增量为两组分位数相减，不是逐对增量的分位数。原定中位数增量不超过 10 ms、P95 增量不超过 30 ms 的目标 **尚未达到**。

这项测量只覆盖 Nu 创建至首个提示符，不包括整个 Windows Terminal 窗口打开时间。没有冷启动分布，也没有按键切换至实际颜色显示的 P95。100 ms 和 500 ms 是 worker 采样等待间隔，不能当作端到端延迟。

## 后台资源

同一测试窗口创建 1、5、10 个独立 Nu 会话，每组约 10 秒，统计 worker 私有内存和进程 CPU 时间差。测试未合成键盘输入，也未固定前台焦点。

| worker 数量 | 私有内存合计 | 单核容量占比 | 整机 CPU 占比 |
| ---: | ---: | ---: | ---: |
| 1 | 3.36 MiB | 0.312% | 0.019% |
| 5 | 16.82 MiB | 1.093% | 0.068% |
| 10 | 33.53 MiB | 0.312% | 0.020% |

整机占比按 16 个逻辑处理器计算。短采样受 CPU 时间粒度、前台状态和系统调度影响，不能据此声称 10 个 worker 比 5 个更省 CPU。内存只包括 worker，不包括 Nu、Windows Terminal 或桌面 GUI。

## 未覆盖范围

同一前台 Windows Terminal 窗口中的标签和分屏共用输入状态，没有独立语言记忆。其他输入法、全部普通与管理员权限组合、标签拖出、快速启停竞争、全部 TUI、WSL 和 SSH 尚未全面验收。

强制终止 worker 可能留下最后的颜色，主动写入光标颜色的 TUI 也可能覆盖指示色。恢复操作见 [CLI 使用说明](CLI.md)。启动增量目标、冷启动和端到端颜色响应仍缺少达标证据。
