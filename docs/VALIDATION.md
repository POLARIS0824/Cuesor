## 功能验证

| 内容 | 结果及证据 |
| --- | --- |
| 中／英颜色通路 | 连续跟随探针记录状态变化与颜色写入；用户确认 `y`。见 `artifacts/follow-probe.jsonl`、`artifacts/follow-verdict.json`。 |

| 日常 Nu／Atuin 交互 | 用户在日常 Atuin Nu 中加载接入脚本，按要求测试搜索、取消／选择记录和返回编辑后反馈“没有问题”。此项为人工验收。 |
| Nu 退出清理 | 最终启动基准的 30 次启用样本全部通过 worker 随根 Nu 退出检查。 |
| 显式停止与清理 | 资源测试的 10 个 worker 已停止退出，测试脚本创建的 Nu 已清理；不会以进程名批量停止日常 Nu。 |
| Rust 自动检查 | 7 个单元测试通过；`cargo fmt --check`、Clippy `--all-targets -- -D warnings` 通过。 |

单元测试覆盖状态分类、查询失败、颜色参数、OSC 指令、状态变化／写入重试、CLI 与会话标识校验，以及 Windows 启动参数引用。自动测试不能证明 Windows Terminal 的实际显示，视觉结论来自用户观察。

验证过程中修复了两类实际问题：

- 最初的颜色演示只在开始阶段写入颜色，后续采样不持续跟随，无法用于视觉验收。改为 `probe --follow` 与明确的 20 秒 `y`／`n` 流程后，用户确认成功。
- 早期 worker 启动方式继承了 Nu 管道句柄，导致实际配置中的 `complete` 等待长期 worker，启动基准超时。改为 `CreateProcessW` 且禁止句柄继承后，最终 30 次启用样本均成功完成。这一结论来自实际交互式 Nu 启动基准，并非仅由参数引用单元测试推断。

## Nu 启动时间

最终测量使用当前 release 和接入脚本，在同一台电脑上交替测量关闭／启用各 30 次，每轮交换先后顺序。临时配置 wrapper 加载用户实际 `config.nu`，Nu 正常加载实际环境配置，禁用历史保存。脚本等待首个提示符可执行命令后，从测试会话读取 `$nu.startup-time`，没有使用跳过日常配置的 `nu -n -c` 作为性能结论。

| 指标 | 关闭 | 启用 | 两组指标之差 |
| --- | ---: | ---: | ---: |
| 中位数 | 273.0005 ms | 294.6774 ms | +21.6769 ms |
| P95 | 364.7360 ms | 421.7629 ms | +57.0269 ms |

原始记录：`artifacts/benchmark/samples.json`，60 个样本。汇总：`artifacts/benchmark/summary.json`。30 个启用样本的 `WorkerCleanup` 全部为 `true`。表内增量是两组分位数相减，不是逐对增量的分位数。

最初设定的中位数增量 ≤10 ms、P95 增量 ≤30 ms 目标 **尚未达到**。保留当前同步调用短命启动器的接入方式，不添加 Nu 后台任务。数据受当时系统活动、缓存、权限和日常配置影响，不能保证其他机器或冷启动获得相同结果。

这项测量针对 Nu 创建到首个提示符的时间，不是整个 Windows Terminal 窗口打开耗时。未测得冷启动分布，也未测得按键切换到实际颜色显示的 P95；100／500 ms 是 worker 的采样等待间隔，不能当成已验证的端到端延迟。

## 后台资源

同一测试窗口内创建 1／5／10 个独立 Nu 会话，每组约 10 秒，统计 worker 的私有内存和进程 CPU 时间差。该测试没有合成键盘输入，属于低活动采样；未固定整个期间的前台焦点，不代表持续输入或大量切换时的最高开销。

| worker 数 | 私有内存合计 | 单核容量占比 | 整机 CPU 占比 |
| ---: | ---: | ---: | ---: |
| 1 | 3.36 MiB | 0.312% | 0.019% |
| 5 | 16.82 MiB | 1.093% | 0.068% |
| 10 | 33.53 MiB | 0.312% | 0.020% |

本机为 16 个逻辑处理器，整机占比由单核容量占比除以 16 得到。短采样的 CPU 时间粒度、前台状态和系统调度使数值不随 worker 数严格递增；这些数据不能用于声称 10 个比 5 个更省 CPU。内存数据仅包含 worker，不包括 Nu 和 Windows Terminal。

## 剩余边界

- 当前会话加载已在用户日常环境通过；未自动修改用户 Nu 配置、Atuin 初始化或 Windows Terminal profile。
- 独立分屏语言记忆不在首版范围内：已接入的分屏／标签跟随同一前台 WT 窗口当前输入状态。
- 其他第三方输入法、完整的普通／管理员权限组合、标签拖到新窗口、极端快速启动／停止竞争、所有 TUI，以及 WSL／SSH 尚未全面验收。
- 非正常强制终止 worker 可能留下最后一次颜色；可以执行 `reset`。主动写入光标颜色的 TUI 也可能覆盖指示色。
- 尚需后续优化或测量的内容包括启动增量目标、冷启动、端到端颜色响应分布；当前结果不应描述为“零开销”或“所有性能目标通过”。
